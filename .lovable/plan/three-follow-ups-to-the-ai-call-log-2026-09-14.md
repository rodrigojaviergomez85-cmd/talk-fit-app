# Three follow-ups to the AI call log

Three small gaps left after the AI cost log landed. No change to what students see or can do.

## A. Story speaking check records its audio length

Today the storybook speaking check asks the transcription provider for the short reply format, which does not include how long the audio was. The length is therefore stored as empty and the call's cost is recorded as zero forever.

- Switch the request to the detailed reply format already used by the Step 2 correction and the final coach.
- Read the duration the same way: a finite number is stored, anything else stays empty.
- Pass that value into the existing cost-log call on the success path.
- Everything else stays as is: same model, same limits, same guards; only the text of the reply is used.

## B. Real number of students per AI feature

The admin cost screen shows "users in the last 30 days" as 0 because the daily totals table has no per-student data.

- A new database migration replaces the cost-center function, changing only that one value: per feature, the number of distinct students with a real (non-denied) AI call in the last 30 days.
- Features with totals but no calls in the window show 0, never blank.
- The admin-only check stays the first thing the function does; nothing else in it changes.

## C. Schedulable cleanup job for the detailed call log

The 90-day cleanup routine exists but nothing can trigger it.

- New endpoint `/api/public/hooks/prune-ai-log`, authenticated exactly like the existing audio-cleanup endpoint: a Bearer job token, with the platform cron secret as fallback.
- The same migration as section B adds the `prune-ai-log` job token row (token generated by the existing default).
- The handler: 30-minute overlap guard (returns 409 while an unfinished run exists), opens a run record, calls the cleanup routine with 90 days, stores the deleted count, stamps the finish and outcome, records errors the same way, returns the count as JSON.
- A comment at the top states the intended schedule is once a day, configured in the Cloud panel, not in this repository.
- Admin alerts screen: the existing cleanup signals are fed by a database health snapshot and adding this job would require new signals/thresholds there, so the screen is left alone as instructed.

## D. Untouched

The call log table, the daily totals table, the totals-updating routine, the shared logging helper, all other endpoints, all quotas, all access rules.

## E. Tests

- Story check: asserts the detailed reply format is requested and that a reply with duration 12.5 logs 12.5 seconds.
- Prune endpoint: rejects with no token and no cron secret; accepts the job token; returns 409 while an unfinished run from 5 minutes ago exists; on success stamps the finish and stores the deleted count from the cleanup routine.
- Full `npx vitest run` and the type check must pass.

## Verification

After a storybook speaking check, the daily totals show `story-say-check` with audio seconds above zero and a nonzero cost. The admin cost screen shows real distinct students per feature. A call to the new endpoint with the job token deletes detailed log rows older than 90 days, leaves the daily totals untouched, and records the run.
